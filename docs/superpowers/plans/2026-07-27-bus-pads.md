# Bus Pads Slice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move `set_pad_mode`, `begin_loop_roll`, and `end_loop_roll` onto the engine cmd/evt bus; delete the three Tauri invokes.

**Architecture:** Engine owns `pad_mode` + `loop_roll_restore` per deck. New kinds emit `Updated` with `pad_mode` on snapshots. Tauri `engine_publish` mirrors `AppState.pad_mode` and loads sampler bank on `Sampler` (Unload-style side effect). FE uses `publishCmd`.

**Tech Stack:** `engine-api` MessagePack wire, `engine-core` control thread, Tauri bridge, Zustand + `wire.ts`.

**Spec:** `docs/superpowers/specs/2026-07-27-bus-pads-design.md`

## Global Constraints

- Library stays off-bus; only bridge hook for `ensure_deck_bank_loaded` on `SetPadMode(Sampler)`.
- Hot cues / saved loops / sampler trigger remain invoke.
- Follow existing performance/sync bus patterns (`bus_performance.rs`, `publishCmd`, empty body + kind).
- Prefer `cargo --manifest-path crates/Cargo.toml`.
