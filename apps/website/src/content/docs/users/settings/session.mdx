**Settings → Session** ("Performance history and session boundaries.") has one card, **Performance history**, whose subtitle is "Log deck playback to XSPF session files under app support."

## Controls

| Control | Type | Values | Default | Effect |
| --- | --- | --- | --- | --- |
| **Record performance history** | header switch | on / off | on | Logs deck playback to session files. |
| **Session idle timeout** | number field, suffix "minutes" | whole number greater than 0 | 5 | Closes a session after a quiet period. |
| **Minimum play duration** | number field, suffix "seconds" | whole number greater than 0 | 5 | Playback needed before an entry is written. |
| **Minimum effective deck volume** | slider | 0–100% | 5% | Level below which a deck does not count as playing. |

**Save** writes these preferences and restarts the audio engine when it is running.

The two other fields and their hints are hidden while **Record performance history** is off:

- **Session idle timeout**: "Close after this long with no qualifying deck output."
- **Minimum play duration**: "Commit entries after this much qualifying playback." Shorter passes over a deck are not written.
- **Minimum effective deck volume**: a deck whose effective level sits below this value does not count as playing. The slider moves in 1% steps.

Typed values are taken as you type. Entering something that is not a whole number above zero (blank, `0`, letters) leaves the stored value untouched rather than resetting it.

## Where the sessions go

Recorded sessions show up in the library's **History** tab, and the files live in the app-support folder alongside `library.db`. See [Install Mixar](/docs/users/getting-started) for the paths.

The exact rules for what opens, splits, and closes a session, and what an exported session contains, are developer reference: [History](/docs/developers/history).
