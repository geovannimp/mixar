**Settings → Audio** ("Engine output and buses.") holds three cards. All three feed the audio engine, so a save on this page restarts it when it is running. For the procedure and the failure modes, see [Audio setup](/docs/users/getting-started/audio-setup).

## Engine

Card subtitle: "Resampler and buffer size."

| Control | Type | Values | Default | Effect |
| --- | --- | --- | --- | --- |
| **Resampler quality** | select | **Low**, **Medium**, **High** | Medium | Quality preset for the resampler that converts tracks whose file rate differs from the engine rate. |
| **Buffer size** | slider | 64–2048 frames in steps of 64 | 512 frames | Frames per mixer chunk. Hint: "Must be a multiple of 64 frames (mixer graph chunk size)." |

**Buffer size** is the one audio control that stays global: it is the chunk the mixer graph renders, and the engine feeds every device stream from it. Each device still calls back on its own period, which the per-device ring buffer absorbs — so the buffer is not a device setting.

## Sample rate and low latency

Each bus carries its own **Sample rate** and **Low latency**, because the two buses can sit on different devices, and those devices can mix at different rates or need different paths. The engine graph runs at the master bus's rate; a preview bus on a device with another rate is resampled in the producer, so it stays time-aligned instead of drifting.

**Device default** follows the rate the device itself mixes at — the rate the system already uses for that output. That is the default on fresh installs, so Mixar asks for the rate the device can actually open. Picking an explicit rate makes Mixar open the stream at exactly that rate; if the device refuses it, the engine does not start and the toast names the rate and the rates the device offers.

Buses that share one device share one stream, so they must share one rate. An explicit rate wins over **Device default** on that device; two different explicit rates for buses on the same device are rejected with *one stream runs at one rate*. **Low latency** never conflicts: it is a hint, so the shared stream uses it when either bus asks.

## Master bus

Card subtitle: "Primary output device and channel routing."

| Control | Type | Values | Default | Effect |
| --- | --- | --- | --- | --- |
| **Device** | select | **System default** first, then every detected output device | System default | Which device the master bus opens on. |
| **Sample rate** | select | **Device default**, then every rate the device reports; the current value stays listed | Device default | Output rate for this device stream. See [Sample rate and low latency](#sample-rate-and-low-latency). |
| **Low latency** | checkbox | on / off | off | Asks the backend for a shorter path on this bus's device. A hint: the driver may ignore it, and a device shared with another bus uses it when either bus asks. |
| **Channel mode** | select | **Stereo pair** / **Mono (fold L+R)** | Stereo pair | One channel on both sides, or a distinct left and right. |
| **Left channel** | stepper | 1 up to the device's channel count | 1 | First channel of the route. 1-based. |
| **Right channel** | stepper | 1 up to the device's channel count | 2 | Second channel. Disabled in **Mono (fold L+R)**. |

If **Left channel** and **Right channel** end up equal, Mixar moves the other one by a channel; on a device that reports a single channel it switches the route to **Mono** instead. Both steppers clamp to the selected device's channel count. While the device list is still loading, the **Sample rate** select is disabled and shows "Loading rates for this device…".

## Preview bus

Card subtitle: "Headphones / cue output when preview is enabled." The card's header switch is **Enable preview bus**, off by default; with it off the route fields are not shown at all.

| Control | Type | Values | Default | Effect |
| --- | --- | --- | --- | --- |
| **Enable preview bus** | switch | on / off | off | Opens a second output for cueing. Without it, headphone cue is silent. |
| **Device** | select | **System default** first, then every detected output device | System default | Device for the headphone bus. |
| **Sample rate** | select | **Device default**, then every rate the device reports; the current value stays listed | Device default | Output rate for the preview device stream. Differs from the master rate whenever the devices do; the engine resamples. |
| **Low latency** | checkbox | on / off | off | Same hint as the master bus, for this bus's device. |
| **Channel mode** | select | **Stereo pair** / **Mono (fold L+R)** | Stereo pair | Same rules as the master bus. |
| **Left channel** | stepper | 1 up to the device's channel count | 3 | First channel of the preview route. |
| **Right channel** | stepper | 1 up to the device's channel count | 4 | Second channel of the preview route. |

What reaches this bus is decided in the mixer. See [Cueing](/docs/users/mixer/cueing).

## What a save rejects

The settings are validated before they are written. A save fails, with the messages in the error toast, when:

- A route's **Sample rate** is zero.
- **Buffer size** is not a positive multiple of 64.
- A route has an empty device.
- A mono route uses channel 0, or a stereo route uses channel 0 or the same channel on both sides.

Channel values the UI clamps on the way in never reach that check; the values above only appear when a settings file is edited outside the app.
