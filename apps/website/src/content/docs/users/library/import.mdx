Mixar reads an existing DJ library and copies its structure into yours: tracks, playlists, cues, and folders. Lists and track references are copied, never audio files, so your music stays where it is. The imported lists become [collections](/docs/users/library/collections).

Two sources ship today, **Mixxx** and **Rekordbox 6/7**, each with its own card in **Settings → Integrations**.

Both imports are **idempotent**: a list whose name and kind already exist is skipped, and cues are written per slot. Running an import twice does not duplicate your library. Missing files are imported as unavailable tracks, which are rows with no playable audio. A list therefore does not silently lose entries when a drive is offline.

## Before you start

You need a Mixxx library, or a Rekordbox 6/7 install, on this computer.

## Import from Mixxx

1. Open **Settings → Integrations** and find the Mixxx card. It is described as *Bring your Mixxx library into Mixar.*
2. Read the card's state. The card checked the standard Mixxx database location at launch.
3. Press **Import from Mixxx library…**. The button is enabled only when a database was found and no import is already running.
4. Read the confirmation. It lists the source path, the track count with a missing-file count, and how many playlists, crates, and watched folders were found.
5. Confirm the import.
6. Wait for the import to finish and read the toast under [Result](#result).

### Mixxx card states

The card reports one of four states:

| State | Meaning |
| --- | --- |
| **Looking for a Mixxx library…** | The check has not finished. |
| **Found:** `<path>` | A database was found and can be imported. |
| **No Mixxx library found on this computer.** | Nothing to import on this machine. |
| **Could not check for a Mixxx library.** | The lookup itself failed; the error is in the log. |

### What Mixxx becomes

| Mixxx | Becomes |
| --- | --- |
| Playlists | Sortable collections, so they keep a manual order column |
| Crates | Unsortable collections |
| Watched folders that still exist | Folder collections that scan subfolders |

Hidden lists are skipped: Mixxx's AutoDJ queue and its own history are not imported. Mixar also creates an unsortable collection named **Mixxx** holding every imported track, so nothing ends up in the library unreachable from a collection. That catch-all is not counted in the playlist totals.

Track metadata comes across where Mixxx stored it: title, artist, album, genre, comment, rating, year, track and disc numbers, sample rate, channels, bitrate, replay gain, and BPM. Keys are normalized to Mixar's musical form, so `8A` arrives as `Am`. A BPM of zero or less is dropped rather than stored as a bogus tempo.

## Import from Rekordbox

1. Open the Rekordbox card. It is described as *Bring your Rekordbox library into Mixar*. It reads the desktop library Rekordbox 6 and 7 keep in `master.db`, so nothing has to be exported by hand.
2. Check the card's state. The card reports the same four states as Mixxx, based on the path Rekordbox itself records in its settings file.
3. Press **Import from Rekordbox library…**.
4. Read the confirmation. It lists the source path, the track count with a missing-file count, and how many playlists, smart playlists, folders, hot cues, and loops were found.
5. Confirm the import.
6. Wait for the import to finish and read the toast under [Result](#result).

Rekordbox encrypts that database. Mixar copies it and its write-ahead log (`master.db-wal`) into a **private** temp directory, unlocks the copy, and deletes it when the import finishes. The shared-memory `-shm` file is scratch state and is not copied; SQLite rebuilds it from the log. The original files are only ever read. Rekordbox can keep running during the import.

### What Rekordbox becomes

| Rekordbox | Becomes |
| --- | --- |
| Playlists | Sortable collections, keeping Rekordbox's order |
| Smart playlists | Sortable collections holding the tracks the smart list matched at import time; the rules themselves do not carry over |
| Playlist folders | A name prefix, so a *Warmup* list inside *House* imports as **House / Warmup** |
| Hot cues | Hot cues on the track, slot and colour included |
| Hot loops | Hot cues that also carry the loop length in beats |
| Memory loops | Saved loops on the track |

Mixar creates an unsortable collection named **Rekordbox** holding every imported track.

Track metadata comes across where Rekordbox stored it: title, artist, album, genre, colour label, comment, rating, year, track and disc numbers, ISRC, sample rate, bitrate, and BPM. Keys are normalized to Mixar's musical form. Two kinds of row are deliberately dropped:

- **memory cues that are not loops** (Mixar stores hot cues and loops only)
- **beat grids and waveforms**, which Rekordbox keeps in separate analysis files rather than in the database

## Result

A toast reports the outcome: **Imported … from Mixxx** or **… from Rekordbox** with per-kind counts, and a `(N missing)` suffix when files were unavailable. Other outcomes:

| Toast | Meaning |
| --- | --- |
| **Mixxx library already imported** / **Rekordbox library already imported** | Nothing new; the lists already exist. |
| **Nothing to import from Mixxx** / **… from Rekordbox** | The database contained nothing importable. |
| **Mixxx import finished with N error(s)** / **Rekordbox import finished with N error(s)** | Partial success. The first few errors are listed under the title. |
| **Could not read Mixxx library** / **… Rekordbox library** | The database exists but could not be parsed. For Rekordbox this is also what a database written by an unknown key would produce. |
| **Mixxx import failed** / **Rekordbox import failed** | The import aborted; the error text is attached. |

## After the import

Beat grids are not part of either migration, so imported tracks have BPM and key but no grid of their own. Queue [analysis](/docs/users/library/analysis) on the imported collections, then correct anything it gets wrong in the deck's [Beat grid](/docs/users/decks/beat-grid) tab.

Metadata that came across wrong is editable in the [track editor](/docs/users/library/track-editing).
